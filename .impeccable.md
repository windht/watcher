## Design Context

### Users

Watcher is for developers and coding agents who organize, run, and inspect APIs locally. In the Realtime workspace, they need to connect to SSE and WebSocket endpoints, observe every event or frame as it arrives, send WebSocket messages deliberately, and preserve the endpoint as an agent-addressable saved request.

### Brand Personality

Precise, calm, tactile. The product should make live transport work feel controlled and inspectable rather than mysterious or noisy. Local-first ownership and trustworthy execution feedback are core to the experience.

### Aesthetic Direction

Use Watcher's cockpit-dense desktop language: deep graphite canvas, raised graphite panes, crisp one-pixel dividers, Geist for interface text, JetBrains Mono for URLs and event payloads, and burnished copper as the only primary action and active-state accent. The Hoppscotch references inform the transport workflow, but the surface should remain native to Watcher rather than adopting purple realtime-console styling.

### Design Principles

- Treat HTTP, SSE, and WebSocket as explicit transport modes with a clear, persistent mode indicator.
- Put lifecycle state, endpoint, and the most recent live data in the same working context; never hide an active connection behind a modal.
- Make logs dense but legible: mono payloads, timestamps, direction/status markers, and controllable clear or disconnect actions.
- Preserve Watcher's existing pane hierarchy and avoid card grids, decorative metrics, and visual noise.
- Keep each transport usable by the built-in assistant and MCP clients through the same saved-request model.
